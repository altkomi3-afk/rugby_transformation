# ラグビー戦術ボード（Netlify版）

ドラッグ操作で赤・青15人ずつのコマとボールを動かせる、ラグビーの戦術ボードです。
代表的な7フォーメーション（キックオフ／スクラム／ラインアウト／アタック／
ドリフトディフェンス／アンブレラディフェンス／22mドロップアウト）を標準搭載し、
標準フォーメーションを編集してそのまま上書き保存したり、独自の「マイフォーメーション」を
追加したりできます。コマは複数選択してまとめて動かせるほか、プレーヤーの動きを
キーフレーム単位で録画し、実際の走るペースに基づいた時間で動画のように再生できます。
ログインすると、それらをクラウド（Netlify Blobs）に保存してどの端末からでも呼び出せます。

## 重要：Netlify Identityについて（2026年9月時点）

以前このプロジェクトは古い `netlify-identity-widget`（CDNスクリプト）を使っていましたが、
Netlifyの案内により**新規プロジェクトでは新しい `@netlify/identity` パッケージの利用が
推奨**されています。今回、認証まわりをこの新しい方式に書き直しました。

- Identity サービス自体は引き続き提供されています（2025年に一度非推奨化が発表されましたが、
  2026年2月に撤回され、現在も正式にサポートされています）。
- ただし有効化する場所やクライアント側のAPIが変わっています。詳しくは下のデプロイ手順を参照してください。
- 参考: [Netlify Identity概要](https://docs.netlify.com/manage/security/secure-access-to-sites/identity/overview/) /
  [Add Identity to your project](https://docs.netlify.com/manage/security/secure-access-to-sites/identity/get-started/)

この方式はドキュメント上の説明に基づいて実装していますが、実際にデプロイしてみないと
分からない部分（特にログインCookieがNetlify Functionsからどう見えるか）が残っています。
うまく動かない場合は、エラーメッセージ（特に「クラウドに保存/読込」を押したときの反応）を
教えてもらえれば一緒に直せます。

## ファイル構成

```
index.html                    ボード本体（静的ページ）。認証UIとログイン後の
                               処理は末尾の <script type="module"> ブロックにあります。
netlify.toml                  Netlify のビルド設定
package.json                  依存パッケージ（@netlify/identity, @netlify/blobs）
netlify/functions/state.mjs   保存データを読み書きする関数（要ログイン、/api/state で公開）
```

## デプロイ手順

1. このフォルダをそのまま Git リポジトリ（GitHub など）に push します。
   npm パッケージのインストールが必要なため、Git連携でのデプロイが必要です
   （ドラッグ&ドロップ配置では動きません）。
2. Netlify のダッシュボードで「Add new site」→「Import an existing project」から
   そのリポジトリを選択します。ビルドコマンドは空欄、公開ディレクトリは `.`（ルート）のままで構いません。
3. デプロイが終わったら、プロジェクトの **Identity** ページ
   （`https://app.netlify.com/projects/<プロジェクト名>/identity`）を開き、
   「Enable Identity」をクリックします。
   - 見当たらない場合は、プロジェクトの設定（Project configuration）内の
     **Identity** という項目を探してください（以前の「Site settings → Identity」や
     「Integrations」タブからは場所が変わっています）。
4. Identity の初期設定は次の通りです（変更したい場合のみ触ってください）。
   - **Registration（登録方法）**: 既定は「Open」（誰でも登録可能）です。
     先生だけに限定したい場合は「Invite only」に変更し、招待したい先生のメールアドレスを
     個別に招待してください。
   - **Autoconfirm（自動確認）**: 既定は「Off」＝新規登録時に確認メールが必須です
     （＝メール認証つき）。開発中だけ確認を省略したい場合はここをOnにできますが、
     本番運用では Off のままにしておくことをおすすめします。
5. 公開後のサイトを開くと、右上に「ログイン / 新規登録」ボタンがあります。押すと
   メールアドレス・パスワードの入力欄が出るので、そこから新規登録またはログインします。
   新規登録した場合は確認メールが届くので、メール内のリンクを開いてから
   もう一度ログインしてください。
6. ログインすると次の機能が使えます。
   - **☁️ クラウドに保存 / クラウドから読込**：現在の配置・矢印・編集済みフォーメーション・
     マイフォーメーションをまとめてアカウントに保存・復元します。
   - **＋ 今の配置をフォーメーションに追加**：現在の配置に名前を付けて
     「マイフォーメーション」として選択メニューに追加します。
   - 標準フォーメーション（キックオフ等）を選んだ状態で配置を編集し「この端末に保存」を
     押すと、次回そのフォーメーションを選んだときに編集後の配置が使われます。
     「標準配置に戻す」でいつでも元に戻せます。

ログインしていない状態でも、標準フォーメーションの利用やコマのドラッグ操作、
複数選択、録画・再生、「この端末に保存 / この端末から読込」（ブラウザ内だけの一時保存）は
そのまま使えます。

## 複数選択と録画・再生について

- コマを**タップ（軽くクリック）すると選択**され、複数選択できます。選択中に
  いずれかをドラッグすると、選択している全員が一緒に動きます。「選択解除」ボタンか、
  何もないフィールド上をクリックすると選択が解除されます。
- 録画は「● 録画開始」→ プレーヤーを動かす → 「Ⅱ キーフレーム」で区切る、を繰り返し、
  最後に「■ 録画終了」を押す流れです。再生時は、キーフレームごとの配置へ全員が
  同時に走って移動しているように補間して表示されます。
- 各区切り（キーフレーム間）の移動時間は自動計算されます。ボードの座標は実際のコートの
  縮尺（トライラインからトライラインまで100m、タッチラインからタッチラインまで70m）に
  合わせてあり、その区間で一番長い距離を動いたプレーヤーが「基準ペース」で走ったと
  仮定して時間を決めます（ボールの移動距離はこの計算に含めません）。
- 「基準ペース（100mを何秒で走るか）」は既定12秒で、いつでも変更できます。変更は
  次に「▶ 再生」を押したときから適用され、保存済みの録画にも遡って反映されます。
  「再生速度」は、その計算結果をさらに何倍速で見るかという、別の調整用スライダーです。
- 録画は「名前を付けて保存」でこの端末・クラウドに残せます。矢印と同様、録画データも
  他のデータと一緒に保存/読込・クラウド同期されます。

## データの保存先について

保存データは **Netlify Blobs**（Netlify に組み込みのデータストアで、追加の
データベース契約は不要）に、ログインユーザーごと（Identity のユーザーIDをキーに）
保存されます。他のユーザーの保存内容は見えません。

## ローカルでの動作確認について

Identity は `netlify dev`（ローカル開発サーバー）では動作しません。ログイン機能を
試すには実際に Netlify へデプロイする必要があります。それ以外の見た目やドラッグ操作は
`index.html` をブラウザで直接開くだけでも確認できます。
